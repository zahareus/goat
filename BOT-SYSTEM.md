# GOAT Bot System

## Що це

Боти — це штучні менеджери, які автоматично обирають гравців на кожен тур. Вони з'являються в standings поруч зі справжніми гравцями. Інші юзери не знають, що це боти.

## Адмін-панель

**Menu → Bot Admin** (видно тільки zahareus@gmail.com)

### Додати бота
1. Введи назву команди (наприклад, "Penalty Kings")
2. Обери стратегію з випадаючого списку
3. Натисни **+ Add Bot**
4. Бот створюється миттєво. `pick_slot` кидається за кривою `rollPickSlot()` — зі зміщенням до початку вікна. В адмінці показується як «as picks open» / «34% into window» / «at last call»

### Поставити на паузу
Кнопка **Pause** — бот не подаватиме піки на наступний тур. Його результати залишаються в standings. Кнопка міняється на **Resume** для відновлення.

### Видалити бота
Кнопка **Delete** — бот зникає зі списку. Всі його історичні результати та піки зберігаються в standings (він просто виглядає як звичайний менеджер, без позначки бота).

## 13 стратегій

| ID | Назва | Логіка |
|---|---|---|
| `form` | Form Chaser | Рандом з топ-3 available гравців за формою (avg BPS за останні 6 GW) |
| `goat` | GOAT Hunter | Рандом з топ-3 за кількістю разів GOAT |
| `rank` | Rank Master | Рандом з топ-3 за Bayesian avg rank (менше = краще) |
| `home` | Home Bias | Тільки домашня команда, топ-3 за формою |
| `away` | Away Specialist | Тільки виїзна команда, топ-3 за формою |
| `streak` | Streak Rider | Гравці з висхідним BPS трендом за останні 3 тури |
| `ironman` | Iron Man | Топ-3 за загальною кількістю зіграних хвилин |
| `contrarian` | Contrarian | З топ-5 за формою обирає тих, кого ніхто не обрав |
| `combo` | Balanced | Зважений скор: form×0.4 + goats×0.3 + rank×0.3 |
| `fwd_only` | Striker | Тільки нападники, топ-3 за формою |
| `mid_only` | Midfield Engine | Тільки півзахисники, топ-3 за формою |
| `def_only` | Clean Sheet | Тільки захисники + воротарі, топ-3 за формою |
| `chaos` | Chaos Agent | Повністю випадковий available гравець |

## Як боти обирають

1. Бот дивиться на всі `scheduled` матчі найближчого GW (пропускає ті, де вже має пік)
2. Для кожного матчу збирає гравців обох команд
3. Відсіює недоступних (chance_of_playing < 75% за даними FPL)
4. **Склади:** якщо RotoWire уже виклав стартові XI (`api/lineups.js`) — лишаються тільки `starter`
5. **Коефіцієнти:** з the-odds-api (`soccer_epl`, 1X2, де-віг, нічия навпіл) виводиться вага домашньої
   команди. Бот спершу кидає зважену монетку — ЯКА КОМАНДА, і аж потім обирає гравця в ній.
   Фаворит 3:1 отримує ~75% піків. Не діє на `home`/`away`/`chaos` — там команда вже задана стратегією.
   🔴 **Рівно ОДИН запит на тур:** перший бот, що прокинувся, оцінює весь тур і пише в `odds_cache`,
   решта читають кеш. Тариф — 500 запитів/МІСЯЦЬ і його ділить ledap, тож ~4-5 запитів на місяць.
   Мапа `NAME_FIX` перекладає скорочення FPL (`Man Utd`, `Spurs`, `Nott'm Forest`) у повні назви букмекера
6. Відсіює тих, про кого нема жодних даних (ні матчів цього сезону, ні прайора минулого)
7. Застосовує стратегію — отримує 3 кандидати
8. Обирає одного рандомно з цих 3

### Прайор минулого сезону

`player_prior` — сумарні BPS/хвилини за минулий сезон з FPL `history_past` (ключ `element_code`,
стабільний між сезонами). Підмішується у `formBps` вагою `PRIOR_WEIGHT=4` і засіває байєсів
середній ранг замість плоскої 15.

🔴 **На старті кожного сезону: `node populate-prior.js`.** `populate-history.js` тут НЕ допомагає —
FPL `element-summary/history` містить лише поточний сезон, тож на GW1 він тягне ~0 рядків.
Без прайора всі 13 стратегій деградують у чистий рандом (інцидент GW1 2026/27: 8 з 10 ботів
взяли гравців Ковентрі проти Арсенала, бот `home` узяв гостя, `fwd_only` — воротаря).

Якщо бот усе ж лишився без даних — це логується і летить TG-алерт адміну, а не тихо.

## Коли боти подають піки

Кожен бот має параметр `hours_before` — за скільки годин до першого кікоффу туру він подає піки.

🔴 **Вікно подачі рахується щоразу заново, воно НЕ стале.** Між турами буває і доба (середній тур), і десять днів (міжнародна пауза). Тому бот зберігає не години, а `pick_slot` — **частку вікна** від 0 до 1:

- **початок вікна** = старт останнього матчу попереднього туру (саме тоді `bot-picks` починає таргетити цей тур); для першого туру сезону — фолбек тиждень;
- **кінець вікна** = перший свисток мінус `BOT_LAST_CALL_HOURS` (3 год);
- бот подає, коли `now >= start + pick_slot × (end − start)`.

Розподіл зміщений до початку (`rollPickSlot()` = `u²`): більшість заходить одразу після відкриття, далі рідше, останній — на останньому виклику. Сенс: гравець, який відкриває застосунок за 5-6 годин до туру, вже бачить повне поле. Під час туру не подає ніхто.

Якщо тур відкрився пізніше за останній виклик (аварійно щільний календар) — вікно стискається, а не пропускається: усі однаково встигають. Перевірено тестами `tests/bot-timing.test.js` на вікнах 24 / 96 / 240 год.

**n8n workflow "GOAT Bot Picks"** (`so4OiXG3rd3LqShU`) запускається кожні 30 хвилин і перевіряє:
- Скільки годин до дедлайну найближчого GW
- Які боти мають `hours_before >= hoursToDeadline`
- Які з них ще не подали піки

Боти з'являються поступово протягом дня перед туром — спочатку ті, що за 24h, потім за 18h, 12h і т.д. Це створює ефект реальних гравців, які заходять в різний час.

## Технічні деталі

### Файли
- `api/bot-picks.js` — генерація піків (POST, захищений GOAT_NOTIFY_SECRET)
- `lib/bot-strategies.js` — ЄДИНА копія логіки стратегій (CJS, під тести). Раніше дублювалась усередині bot-picks.js
- `populate-prior.js` + `sql/player-prior.sql` — прайор минулого сезону
- `api/lineups.js` — стартові склади RotoWire (спільні з notify.js)
- `api/bot-admin.js` — CRUD для ботів (захищений Supabase auth token)
- `sql/bot-migration.sql` — DDL для колонок

### Колонки в profiles
- `is_bot` (BOOLEAN) — чи це бот
- `bot_active` (BOOLEAN) — чи активний (pause/resume)
- `bot_strategy` (TEXT) — ID стратегії
- `pick_slot` (NUMERIC 0..1) — у якій точці вікна подачі бот подає піки
- `hours_before` (INTEGER) — ЛЕГАСІ, лишається лише як фолбек для ботів без `pick_slot`

### Ручний запуск (для тестування)
```bash
curl -X POST "https://goatapp.club/api/bot-picks?secret=$GOAT_NOTIFY_SECRET"
```
(Secret зберігається в Vercel env vars та n8n workflow)

### Env vars
- `SUPABASE_SERVICE_ROLE_KEY`, `GOAT_NOTIFY_SECRET` — обов'язкові
- `THE_ODDS_API_KEY` — the-odds-api (той самий ключ, що в ledap). Без нього боти обирають команду 50/50 і пишуть warning у лог
- `TELEGRAM_BOT_TOKEN`, `GOAT_ADMIN_CHAT_ID` — алерт про деградацію
- 🔴 Як `GOAT_NOTIFY_SECRET` доїжджає до ендпоінтів — див. «Cron endpoints & their secret» у `CLAUDE.md`. Коротко: Photo Sync ходить заголовком `x-goat-secret` через n8n-credential «GOAT notify secret (x-goat-secret)» (`BWtklpJJY4Dt5qZQ`), решта воркфлоу — досі `?secret=` у тексті URL ноди.
